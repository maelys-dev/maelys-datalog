# 0.18.0 release review

Status: both concrete Python reports accepted by David on 2026-10-01 for
0.18.0. Merge, cut and publication are authorized after the checks and release
gate. The acceptance and attribution limits are recorded below; no measurement
classification is changed.

## Candidate and compatibility

Signed main `a279e6a30b186b1bc9071a225dc15e341d59a51d` contains #159
(precompiled Python wheels), #160 (allocator proposal only), #161 (per-bank
window deltas), and #162 (SDK headers). Its complete tree equals the reviewed
#162 head `8593027451cb06538e392e61c0c47f77431436fc`.

The SDK has eleven installed headers with a documented source include migration,
without forwarding headers. Consumer API 2, program ABI 2, backend ABIs 5/6/7,
public declarations, macros, layouts, callbacks and C++ type linkage are
preserved. Both manifest loaders remain because their validation profiles differ.
See [the header map](../sdk-headers.md) and
[#162](https://github.com/maelys-dev/maelys-datalog/pull/162) for the downstream
replay, including the distinct ABI 7 window packet-test migration.

The allocation service is not implemented. Its future caller descriptor belongs
in `maelys/datalog_resources.h`; its provider service belongs in
`maelys/datalog_backend.h`. Fixed storage guarantees are unchanged.

## Decision and remaining ceremony

On 2026-10-01, David explicitly accepted Python runs 36896136426 and
36906281900 for 0.18.0 and authorized the cut after checks and the release gate.
His decision cites an independent observation of identical ordinary native
instruction counts between v0.17.0 and `a279e6a`, and unchanged `engine.py`.
The latter source equality was also checked locally. The independently reported
instruction observation is not represented as a new count collected by this
release preparation.

For this release decision, the alerts are treated as unattributed measurement
variability. Both reports remain `review_required`; their raw observations,
including recurring and isolated tails, are retained. Equal instruction counts
do not prove equal cycle costs or identify a code-layout/hardware mechanism.
There is no performance claim for precompiled wheels. This explicit 0.18.0
acceptance is separate from the historical 0.17.0 decision.

The remaining ceremony is to merge the changelog PR, run the pinned socle's
two-stop cut, verify the exact version commit, and verify the receipt-bound
tagged build artifacts before the release gate.
Published archives, wheels, npm package and channel receipt are then checked
against the actual publication; a candidate receipt is never rewritten as one.
