## Scope and qualification

The candidate includes fixed session resources / backend ABI 6 (#142), bounded
native session-storage recycling (#143), and prepared-request diagnostic and
null cross-check tooling (#144). The proposed release documentation changes no
runtime, binding, build flags or measured harness. `VERSION` remains 0.13.0 in
this review PR; the release socle prepares the version change after the decision.
The unmerged host-delta experiment, prepared-IDB-span optimization and JavaScript
binding work are outside this candidate. No downstream pin or provider is migrated.

[CI 36610274367](https://github.com/maelys-dev/maelys-datalog/actions/runs/36610274367)
passes all 17 checks on the exact measured main commit, including native tests,
installed SDK/Python, allocation contracts, sanitizers, fuzz and both Emscripten
versions. The qualification details remain in
[session resources](session-resources.md) and
[session recycling](session-recycling.md):

- Normalized E/D/S/T reach both ABI 6 sizing and preparation; program/build
  bounds do not become consumer quotas. ABI 5 defaults remain supported;
  unsupported nondefault combinations are explicitly refused.
- E/D size payload reservations. S/T are exact admission limits, but lowering
  them does not yet shrink the profile-sized dictionary reservation. Elastic
  resources and allocator extensions remain reserved and rejected.
- Linux/macOS × SMALL/LARGE exercise separately compiled old/new callers and
  providers: 38 successful combinations and two expected new-API/old-host link
  rejections per configuration. Synthetic XLARGE records test public boundaries;
  they do not constitute an XLARGE engine profile.
- Fourteen fixed-resource mutants and nine recycling mutants per profile are
  detected. Recycling includes real library unloads and disabled-allocator warm
  hits, caller-owned storage exclusions, leases and concurrent ownership.
- The clean installed LARGE SDK replay passes the private ABI 5 consumer at
  `608aa9e2485a8d06350850314720fecdc5f90991`: 10/10 normally and 10/10 with
  allocation hooks throughout SDK and consumer. This is compatibility evidence,
  not an ABI 6 implementation in the private provider.

One equal-sized idle engine-owned host block can be reused; misses still allocate.
The retained block is additional to live reservations. Qualified Linux x86_64
layouts retain at most 793,920 bytes in SMALL or 1,140,032 in LARGE; bounds derive
from the compiled layout. Python/CFFI, conversions and other resources still
allocate. Native teardown drains the slot; Emscripten does not cache it.
There is no allocator-policy change, growing cache or secure-erasure guarantee.

resource contract and bounded recycling. The recommendation is to accept a
**documented performance tradeoff**, including the complete-request increases
above, all phase/cold observations and the preserved historical unresolved events.
