## Maintainer decision

On 2026-10-02 David explicitly accepted this concrete report for 0.19.0 and
authorized publication after checks and the release gate. His decision retains
the sole recurring microsecond-scale close phase and the unchanged binding.
The native-count statement in the authorization is corrected here: the report
shows an **increase of 25–52 instructions per request**, not a decrease of
18–52. The acceptance is recorded without rewriting that measured result.

Small native instruction differences do not prove equal cycle costs or identify
code placement, runner variance or an engine mechanism. All raw classifications
and observations remain. This is a shared-installed-SDK Python campaign, not
one for the separate statically linked precompiled wheels; no wheel performance
is claimed. Version/documentation-only release preparation does not itself
require another benchmark.

The local `scripts/release-gates.sh` passes on reviewed tree `9d2ba26`: Clang
and GCC/Linux in a disposable Ubuntu 24.04 ARM64 container, no skipped gate.
Pinned-socle v0.62.2 preflight passes. The npm channel rehearsal passes against
published v0.18.0 with no registry write; publishing/assembly scripts are
byte-identical to the candidate. Its first attempt from the candidate checkout
correctly refused the historical receipts' different commit. The successful
replay uses the exact v0.18.0 checkout; both attempts are retained locally.

The remaining ceremony is the merge of #168 and two-stop signed cut,
verification on the exact release commit and receipt-bound tagged artifact
verification. The release environment gate precedes publication. Candidate
receipts never become publication evidence by manual rewriting.
