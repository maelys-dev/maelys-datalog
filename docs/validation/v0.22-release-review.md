This dated changelog candidate carries the compatibility freeze for the existing
0.x public contract. No 1.0.0 is planned here. The freeze takes effect only if
0.22.0 is explicitly approved and published. `VERSION` is not changed by this
review; no release cut has been started.

## Candidate and compatibility correction

The measured candidate is signed commit
`5f668293241a0070202b06f177d2c87ea2318f2e` on main, after the signed #180 fix
was merged. The fix centralizes policy-handle liveness across count, id,
fingerprint, statistics and session creation. It makes a caller-owned handle
with zero references return `INVALID_STATE` even after its storage has been
cleared and remains addressable. The named test checks all five APIs after free,
output status/values, then reuses the same storage. The two rebuilt mutants that
omit reference checks in id and statistics are each caught by that test.

The numerical compatibility declaration covers consumer API 2, program ABI 2,
backend ABIs 5/6/7, current arity 4, eight current IR body literals, 32 current
IR variables, and the eleven existing installed headers. It preserves explicit
future negotiation of additional record families. The freeze review and
compatibility declaration remain individually linked in this PR stack until
integrated; do not infer release approval from either document.
