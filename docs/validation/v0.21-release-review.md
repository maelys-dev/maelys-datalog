## Storage and compatibility

Private fact records use 40 naturally aligned bytes rather than 72, with
canonical zero inactive positions and explicit aggregate-premise metadata.
Public values/facts/views/IR and backend ABIs retain their layouts, as do the
compiled-rule records and program/execution fingerprints. Caller-owned
storage users re-query requirements and alignment for the actual SDK/program,
options, profile and provider; private byte sizes are not a compatibility
promise. Allocation accounting and scoped Callgrind instruction evidence are
recorded in #175, separately from latency.

A live empty policy set now returns OK/zero from policy_count and OK with its
specified v1 fingerprint from policy_fingerprint. Previously those observations
returned INVALID_STATE despite a successful load and valid releasable handle.
Nonempty-set fingerprints retain their serialization. The named allocation
witness covers both empty and disabled manifests, all manifest loaders,
caller-storage reuse, statuses and output preservation; Python and native/WASM
JavaScript expose empty sets without raising.

The compatibility page describes the freeze independently of a major version
number, including future wider record families and explicit capability/status
rejection. It does not freeze internal storage sizes or imply new language
support.
